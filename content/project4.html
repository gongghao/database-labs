PROJECT 04

数据库设计与应用

把业务需求转化为 E-R 图、关系表与可操作的 Access 应用。

1. 明确业务场景

可基于 University 数据库设计学生成绩管理系统，也可选择图书馆、库存、网上书店等场景。先写出谁使用系统、需要记录哪些信息，以及系统需要完成哪些操作。

2. 设计 E-R 图与关系模式

  1. 识别实体、属性及实体之间的联系。
  2. 说明联系的基数与业务约束，选择稳定、清晰的主键。
  3. 设计至少 3–4 张相互关联的表，处理多对多关系，避免将重复信息堆在一张表中。
  4. 检查字段命名、数据类型、主外键与规范化，解释与原始 University 设计相比所作的改进。

可以参考原始数据，但不要直接沿用不适合新场景的键或字段含义。根据自己的业务准备测试记录。

3. 在 Access 中实现应用

建立数据表与关系，利用 Access 自带工具制作界面 / 窗体、查询与报表。查询应体现实际业务需求，避免只有单表全部记录展示。通过正常与异常输入验证功能。

本项目没有独立的新数据集。可从 University 原始数据开始，再按应用需求设计和补充测试数据。

4. 完成报告与交付

报告至少包含业务背景、E-R 图、关系模式、功能设计、非简单查询、界面与运行结果截图。可参考提供的 report_example.docx，但图表和内容须反映自己的实现。

提交 report_A4.doc / .docx / .pdf 与 university_A4.mdb / .accdb，按 学号-姓名-Project-4.zip 打包。
